# Frontend dependency release correction

This independent security correction preserves GPT-6 configuration and unrelated MCP/submission working-tree edits.

Dashboard/Auth upgrade Next.js 16.2.6 to stable 16.3.8 to remove current framework advisories and permit patched sharp 0.35.5. Their direct PostCSS is 8.5.28; the old vulnerable global 8.5.14 override is removed. Firebase moves from 12.13.0 to stable 12.19.0. MCP upgrades the public SDK from 1.29.0 to 1.32.1 and Vite from 8.0.14 to 8.0.16. Compatible transitive lock refreshes patch source-map-js, protobufjs, websocket-driver, browserslist, nanoid, proxy-addr, qs, Hono, fast-uri and ip-address without application contract changes or package major migrations.

Firebase's current stable parent still constrains the unused Firestore Node implementation to vulnerable gRPC `~1.9.0`. Both apps own a real, parent-scoped [npm security override](https://docs.npmjs.com/cli/v10/configuring-npm/package-json/#overrides) to published `@grpc/grpc-js` 1.13.6. This is outside Firebase's declared minor range; it retains the gRPC 1.x public metadata, credentials and generated-client APIs. The application only uses supported public `firebase/app` and `firebase/auth` imports. No Firestore feature exists; changing to internal @firebase packages would be unsupported. Clean install, current Auth tests, TypeScript/build, lock audit and final runtime tracing remain required. This does not claim end-to-end Firestore compatibility; remove the override when the parent fixes its constraint.

The only high finding allowed to remain is unpatched [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm): Tailwind 3 → chokidar/fast-glob/micromatch → braces in Dashboard/Auth, and vite-plugin-singlefile → micromatch → braces in MCP. Current parents retain this path and braces 3.0.3 has no patch. Tailwind input paths are checked-in source globs; singlefile's inlinePattern is unset/empty and never invokes micromatch. No public request input reaches these build tools. Removing parents would change CSS or widget packaging; a Tailwind 4 migration is outside this narrow correction.

Every package runs a blocking production audit at the existing **high** threshold and a complete retained audit. Only the exact braces advisory and exact effects in these three reviewed parent chains may be conditionally non-blocking; each lock node must be dev-only. New high/critical findings, changed upstream patch metadata/latest version, changed parents or audit errors block. There is no configurable exemption list. Moderate/low findings remain visible under the unchanged high-severity CI contract. The remaining moderate Tailwind selector-parser advisory concerns trusted build CSS, is absent from runtime, and requires a separate Tailwind/PostCSS migration for a compatible complete removal.

Infrastructure CI additionally inspects all three final Linux runtime images, recursively rejecting the development packages and selector-parser, and verifies patched sharp/gRPC when present. This independent mandatory image check is part of release readiness; a passing lock-only audit alone is insufficient. Dependency Review availability cannot bypass these package-manager checks, which run even when the GitHub feature succeeds.
